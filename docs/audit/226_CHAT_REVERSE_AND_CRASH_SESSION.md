## Диалоговые сообщения
GAMMA news_manager.send_task, relocate_money и relocate_item при is_talking вызывают give_talk_message2. CScriptGameObject::AddIconedTalkMessage обращался к локальному TalkMenu; на dedicated CurrentGameUI отсутствует, поэтому сообщения молча терялись. Теперь сообщения удалённого Actor проходят его AddGameNews -> уже существующую отправку владельцу, как eTalk. Локальный co-op Actor получает чат без зависимости от SP TalkMenu. Чужой клиентский Actor не может показать сообщение владельцу. SP/NPC ветка сохранена. Клиентский on_task добавляет отсутствующую в GAMMA callback сводку complete; new/fail остаются серверными, без дублирования.

Реальные GAMMA функции уведомлений и клиентский callback выполнены в Lua5.1; native fixture извлекает настоящий AddIconedTalkMessage и проверяет двух владельцев, локального/чужого Actor, пустую иконку и SP. Это не интеграция с живой UI/сетью.

## Задний ход
В netcoop manual branch S всегда тормозила; переход тормоза в R был прямо отключён в UpdateBack, а R разгонялся на W. Теперь S тормозит движение вперёд, у безопасной остановки выбирает R и даёт тягу; отпускание S убирает тягу. W возвращает R->1 только после безопасной остановки. Высшие передние передачи по-прежнему вручную, зажигание отдельное, ручник блокирует тягу; NaN скорости не даёт тягу. Нативный fixture сохранённых методов проверяет оба направления, двигатель off, совместные педали, движение/остановку, ручник и SP/вертолётный путь.

## Старая lease после падения процессов
Живой владелец удерживает OS ownership-файл эксклюзивно. Раньше после смерти процесса новый сервер успешно брал этот файл, но ещё отказывал по старому timestamp. Новая запись online имеет дополнительный маркер oslock1 (старые reader всё ещё читают первые два числа). Для отмеченной записи полученный эксклюзивный lock доказывает отсутствие прошлого процесса — stale heartbeat не блокирует вход. Старый формат без маркера сохраняет консервативный TTL. Реальные Windows multi-process проверки сохраняют конкурирующего/зависшего владельца, независимые аккаунты, ошибки записи и legacy TTL, добавляют немедленное восстановление после TerminateProcess. Route/ticket и обязательная долговечная запись персонажа не обходятся.
