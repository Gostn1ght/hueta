# Предметы заданий: постоянный UID и замена сетевых ID

14.11.2026, кандидат, не выпущен.

Подтверждённая причина отказов сдачи после смены сервера: character_spawn_saved_items читает сохранённый Spawn packet, затем сбрасывает item->ID и ID_Phantom в 0xffff перед spawn_end. GAMMA хранит item_1_id/item_2_id в persistent vars. Получается тот же сохранённый экземпляр с другим сетевым ID, а квест ищет прежний; прежний ID может уже принадлежать другой вещи.

Исправление:
- В момент настоящего восстановления native сохраняет пару сохранённого ID и выданного ID и передаёт таблицу в существующий серверный Lua restore callback четвёртым аргументом. Это runtime metadata; формат сохранения NCH не меняется. Старый Lua с тремя аргументами игнорирует лишний аргумент.
- Зарезервированные оригиналы, возвращённые с трупа, включаются в mapping с неизменным ID. Лут, не возвращённый этому персонажу, туда не попадает.
- До load_state заданий мигрируются только ссылки на подтверждённый восстановленный предмет нужной секции с настоящим владельцем. Подходящая по секции копия не считается оригиналом. Это даёт путь старым сохранениям без записанного в квесте UID.
- Для дальнейших сохранений item_1_uid/item_2_uid записываются строками, без потери точности 64-bit UID в Lua double. Перед сохранением, до/после проверки задания и после восстановления ID связывается с этим UID.
- Сдача точных квестовых экземпляров сверяет и владельца, и UID. Неоднозначный mapping/чужой предмет/неустановленная legacy-идентичность не получают выдуманный успех. Известный UID, оставленный на другом сервере, удерживает задачу в ожидании вместо ложной смерти/утраты.

Проверки: реальный Lua5.1, UID 9007199254740993, сетевой ID 1301->1309, копия той же секции на старом ID, точная миграция legacy mapping, неоднозначный mapping и чужой владелец. Дополнен существующий native character restore fixture: настоящий Spawn_Read/spawn_end boundary, пары ID, передача mapping в настоящий progress restore и все прежние admission/rollback checks. GCC/MSVC только в Actions. Полный native CI изменения ещё требуется.

Ограничение: если старый предмет не находится в сохранённом инвентаре и для него никогда не был сохранён UID, новый сервер не может доказать его личность. Его нельзя подменять произвольной вещью той же секции. Общая мировая миграция динамических квестовых предметов, оставленных вне инвентаря, требует отдельного сервиса мировых сущностей.
