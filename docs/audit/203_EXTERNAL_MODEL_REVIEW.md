## Что принято после проверки

В client_cluster_transfer подтверждено использование client_login() — запомненной парольной учётной записи — вместо активной Firebase-сессии. Предложение внешней модели адаптировано: добавлен общий client_connection_login, которым пользуются и auth-пакет, и команда редиректа. Облачная личность выбирается только при том же признаке активного токена, что используется для auth mode. Устаревшее запомненное имя не меняет пользователя редиректа. Нативный стенд проверяет смену A→B, пустой облачный токен и отключённый облачный вход. Проверка выполняется в CI, не локальной компиляцией. Эта правка не является доказательством устранения Wrong password, поскольку сам сервер уже сравнивал UID текущего auth-пакета.

## Что отклонено

- Первый ответ по устройствам предлагал прямой g_SetAnimation из OnEvent, утверждая, что обычные обновления не вызывают анимацию. Actor.cpp/Actor_Network.cpp содержат регулярные вызовы. Патч не применён.
- Второй ответ по устройствам утверждал, что торсовый раздел не включает руки, и смешивал устройства с m_netcoop_tp_item (это отдельный реквизит потребления/RP). Реальный OMF разобран: torso включает bip01_l_hand, bip01_r_hand, предплечья, плечи и пальцы. Патч отсутствует, вывод не принят.
- Патч возрождения оставлял survival_pending=true для непустого списка и повторно добавлял те же ID в entities. Lua claim возвращает непустую строку ID при успешном завершении, а не пустой список; предложенная новая логика не завершалась бы и раздувала список. Не применено.
- Патч сетевого буфера считал NET_Last указателем на удаляемый элемент NET. В Actor.h и CustomMonster.h это значение net_update, а Actor_Network.cpp уже присваивает NET_Last=cur. Предложенная замена на NET.back() уничтожает выбор интерполированного состояния. Не применено. Заявление о необходимости сброса полей старых объектов не учитывало их удаление до client_sync_reset.
- Дополнительные изменения cache_characters и EnterWorld не приняты: выбор кэша уже переопределяется облачным UID в character_cache_path, а EnterWorld уже обновляет текущий облачный логин. Предложенный diff также оставлял парольный путь без инициализации login.
