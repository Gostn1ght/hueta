# Стабильная идентичность анимаций NPC

13 ноября 2026. Кандидат, не выпущен. КРИТ-02/03 остаются открытыми до сборки и игрового воспроизведения.

## Проверенный дефект протокола

CAI_Stalker отправлял MotionID.val: индекс анимации и слот локальной OMF-библиотеки. Наборы и порядок библиотек могут различаться. Контрпример: у сервера slot0=walk, slot1=idle; у клиента slot0=idle, slot1=walk. Сырой серверный ID idle выбирает у клиента walk. Дополнительные библиотеки загружаются через список файлов. Это подтверждает дефект транспорта, но не доказывает, что все наблюдаемые Т-позы/рывки имеют единственную эту причину.

## Изменение

Три прежних u32 несут FNV-1a имени цикла, а старший бит mode обозначает новый формат. Размер пакета не меняется; CSE и промежуточные сетевые состояния переносят байты без переинтерпретации. Клиент снимает маркер перед выбором режима и разрешает хеш в собственный MotionID. Совпадающие имена в разных слотах следуют ID_Cycle_Safe: последний слот имеет приоритет. Разные имена с одинаковым хешем навсегда исключаются из таблицы; третья коллизия не возвращает неоднозначный хеш обратно. Алиасы одного ID выбираются детерминированно. Invalid sentinel исключён.

Неизвестный/неоднозначный обязательный цикл и несуществующий legacy ID возвращают управление обычному выбору анимации, без индексирования недоверенного значения. Неизвестная голова в режиме3 допускается, torso/legs обязательны. Dead/mode0 сохраняют прежнее поведение.

Новый клиент принимает прежний raw-формат только для существующих локальных циклов; при разном порядке OMF он не может угадать имя из старого ID. Старый клиент не умеет stable-формат и выбирает локальное поведение для неизвестного mode. Для корректного сетевого результата нужно обновлять сервер и клиенты вместе.

## Кэш и одиночная игра

Таблица принадлежит менеджеру NPC. Она строится лениво только при включённом netcoop, очищается в reinit/reload; вне netcoop экспорт остаётся прежним и сортировки при загрузке NPC нет. Снимки проверяют только количество и идентичность слотов, а не все имена. Менеджер удерживает refcounted shared_motions, чтобы старые данные не получили новый смысл при повторном использовании адреса; сам renderer/visual не удерживается. Замена слотов даже по тому же адресу visual вызывает перестроение. При смене visual без согласованного reload менеджер не играет чужую таблицу.

## Проверка

Проверяет перестановку слотов, три коллизии, повтор имён, алиасы, unknown/invalid, legacy и mode0/1/2/3, сброс, замену motion-данных при том же адресе visual и 1000 снимков без повторного обхода имён. Внешние зависимости подменены узкими заглушками, а не незавершённым наследником интерфейса рендера. Результат CI фиксируется после запуска.
