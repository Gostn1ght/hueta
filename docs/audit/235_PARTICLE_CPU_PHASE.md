# Independent particle math on the CPU pool

Sixteen actions now run disjoint ranges on the synchronous bounded pool: copy position, damping, explosion, gravity, scatter, move, orbit line/point, restore, speed limit, target color/size/rotation/velocity, vortex and turbulence. Action order is unchanged. Action age/time counters advance on the owner exactly once after the fence. Color and turbulence scratch variables are private to each particle. Noise tables initialize on the owner before workers read them.

Source, sink, kill, random acceleration/displacement/velocity, jet, follow, gravitation and velocity matching retain their original order and thread: they use shared RNG, callbacks, changing storage or neighbouring particles. The existing effect and action-list ownership is unchanged, and no owning effect object is copied. Each action joins before the next one executes. `-cpu_serial` or `-cpu_particles_legacy` selects serial ranges. Heavy noise starts at1024 particles, heavier force/trigonometric math at4096, cheap memory operations at16384; smaller effects avoid scheduling overhead.

The range helper uses512-particle chunks and at-most-once claims, so scheduler failure after partially completed work cannot double velocity/age changes. CI compares the actual modified Execute bodies and noise implementation against frozen pre-change serial Execute bodies from5e94308d9. It covers16 actions, branching force radii, time branches, chunk/threshold boundaries, canaries, stable counts and injected partial scheduler failure. Core vector/color/effect types are boundary doubles; pVector operators and Particle layout are actual source. The full DX8/DX11 build is required to validate engine ABI. CI timings are fixture measurements, not game FPS evidence. Native/game validation pending at this commit.
