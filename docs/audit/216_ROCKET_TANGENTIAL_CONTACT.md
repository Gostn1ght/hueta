# Коррекция точки удара ракеты при касательном контакте

14 ноября 2026. Подготовлено, не выпущено.

CustomRocket::ObjectContactCallback при pushing_neg делил neg_tri.dist на скалярное произведение скорости и нормали треугольника без проверки делителя. Параллельное направление даёт ноль, а малый делитель — потенциально переполнение float. Нечисловая координата затем передавалась Contact, точке взрыва и позиции ракеты. Это конкретный воспроизводимый дефект математики контакта; он не сопоставлен с новым пользовательским дампом и не считается объяснением всех вылетов гранат.

Выделен rocket_penetration_position: проверяет конечность входов и величину делителя до деления. Промежуточная арифметика выполняется в double и проверяется на представимость в float перед сужением, чтобы переполнение не произошло ещё до _valid. Отказ не меняет исходную допустимую точку попадания. Координаты предыдущего контакта также используются лишь если конечны. Обычная формула проекции сохранена.

Actual-source check-native-projectile-lifecycle исполняет эту функцию: положительное/отрицательное направление проекции, нулевой и малый делитель, NaN/Inf, переполнение результата, нечисловой вектор, совпадение входного/выходного объекта. Для экстремального конечного входа отдельно проверяется отсутствие FE_INVALID/FE_DIVBYZERO/FE_OVERFLOW. Существующие проверки ownership/relcase и быстрых снарядов сохранены. Нативное исполнение только в GitHub Actions; локально проверены синтаксис Python и diff.
