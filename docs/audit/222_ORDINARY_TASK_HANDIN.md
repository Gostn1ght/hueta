# Обычные задания GAMMA: переходы и сдача

Статус: кандидат, не опубликован. 14.11.2026.

Подтверждены ошибки:
- Native UpdateTasks пропускал задания с другой исходной картой, а cluster helper отменял чужую цель. Убраны оба ограничения; исходная карта сохранена как метаданные.
- Отложенный task_callback вызывал give_reward без текущего собеседника. GAMMA возвращалась без выплаты. При отсутствии binder callback у dedicated actor добавлен однократный серверный fallback; существующий callback не дублируется.
- Конструктор GAMMA читал reward_item из reward_money (например, предмет с секцией 5000). Runtime hook исправляет поле, не заменяя исходный task manager.
- Сдача через set_task_completed доверяла флагу диалога. Теперь перепроверяются активная задача, нужный NPC, status/stage и реальный инвентарь. Конкретные экземпляры/порции перемещаются до награды и репутации. Недостаток, предметы на поясе, неподходящее состояние и отказ передачи не дают выплату; отказ посреди пачки возвращает уже перемещённые экземпляры.
- У multi-fetch private recipe и bounties_by_id были глобальными и отсутствовали в снимке персонажа. Переключение Actor теперь сохраняет эти модули в его pstor, восстанавливает их до task constructors, очищает при новой жизни. Нет заимствования рецепта другого игрока.
- Ошибка необязательного quest functor/world/emission больше не прерывает обновление остальных задач.

Проверки: реальный Lua5.1/Lupa и извлечённые исходные функции GAMMA, сохранение A->B->A, разные игроки, свежая проверка стадии, неверный NPC, недостаток предметов, полный откат пачки, один платёж, частичные порции и multi-fetch required/optional без повторного использования одного ID. Native fixture извлекает целиком UpdateTasks и ChangeStateCallback; выполняется только в GitHub Actions (GCC/ASan/UBSan и Windows/MSVC). CI 43622699868 прошёл ресурсы, Lua, шейдеры и GCC. Windows fixture остановилась на C4458: имя поля заглушки tasks совпало с локальным именем извлечённого настоящего метода. Поле переименовано в fixture_store; сам native метод не изменён ради теста. Полная пересборка ещё нужна.

Дополнение: bounty/assault сохраняют имя, секцию и карту цели при назначении; чужая карта, отсутствующий или повторно занятый ID не засчитываются как смерть/зачистка. Исходный GAMMA status functor выполняется на карте цели, подтверждённый успех переносится с персонажем обратно к заказчику, повторный заказ очищает старое доказательство. Выполнены реальные bounty/assault функции с мировыми API-заглушками. Артефакт-комбинация сдаётся вместе с возвратом пустого контейнера владельцу; отказ создания контейнера откатывает оригинал. Добавлен общий preflight для remove_item (весь набор разных секций), remove_quest_item (точные оригинальные ID), remove_delivery_item. Условные будущие ветки доставки отклоняются до расхода, а не расходуют обе ветки. Все текущие материальные on_complete конфиги проверены: условных веток и смешения generic/fetch среди них нет.

Ограничения: proof не заменяет общую мировую БД/события; убийство на другом сервере без присутствия владельца задания ещё требует межсерверного переноса событий. Потерянные/переименованные динамические цели не получают выдуманный успех. Отдельные money-payment/hostage/story эффекты не объявлены полностью проверенными этим receipt. Durable crash-atomic награда не реализована; Lua rollback не является дисковой транзакцией. Реальные два клиента, карты, UI награды и репутационный доступ торговца остаются интеграционной проверкой.
