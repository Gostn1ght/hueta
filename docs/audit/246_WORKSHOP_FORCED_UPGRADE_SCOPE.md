# Restore workshop forced-install context after failure

TASK-E05-006: the server RPC routes owner-checked workshop requests through netcoop_server_compat.item_action to netcoop_workshop.upgrade, with the requesting actor bound by the owner. GAMMA's UIWorkshopUpgrade evaluates available kits and installed/pair/parent restrictions, then Upgrade temporarily sets inventory_upgrades.force_upgrade=true to bypass mechanic prices for kit-based installation. Its exceptional path never reset that shared global. GAMMA rank-pricing precondition/effect functors use the same flag for subsequent mechanic requests.

The server wrapper now captures the exact previous nil/false/true value and restores it after success or error, then rethrows the original failure. It retains GAMMA installation and kit consumption, existing rejection/replay rules, and quietly's UI helper restoration. No native, RPC or character persistence protocol change.

Actual Lua5.1 regression tests run the deployed GAMMA fixture leaves, including the keep-crafting-window override and actual rank pricing. Controlled native installation throws after force_upgrade is set. With the old unguarded call, an isolated counterfactual reproduces a mechanic installing with zero money. With the fix, zero-money requests are rejected. Success/exception preserve each previous flag value, UI helpers are restored, a successful new upgrade consumes one kit and replay neither installs nor consumes again. Fixtures use inventory/native boundaries; they do not prove live multi-client, restart or crash-atomic payment behavior. The combined client/server fixture temporarily selects its captured dedicated Upgrade leaf when testing the server after the client hook has loaded; production source is not modified by that selection.

Local check-netcoop-workshop.py PASS. No native/game/GPU execution, local installation or public release.
