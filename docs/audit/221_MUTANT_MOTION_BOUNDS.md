# Границы сетевой анимации мутантов

14 ноября 2026. Кандидат для ВХОД-01/КРИТ-03, не выпущен.

CBaseMonster::netcoop_play_motion проверял только sentinel u32(-1), затем использовал серверный MotionID для LL_GetMotionDef и LL_PlayCycle. Renderer индексирует m_Motions[slot] и motion_defs[idx] без безопасного отказа. Если клиентская модель не содержит переданной библиотеки/цикла, это выход за границы ещё до выбора анимации. Также сетевые phase/speed не проверялись на NaN/Inf, хотя используются в blend time/speed.

Перед любыми обращениями/перебором blends добавлена O(1) проверка slot по LL_MotionsSlotCount и idx по размеру definitions текущей модели. На каждый вызов берётся refcounted shared_motions текущего слота; данные старой модели не кэшируются. Несуществующая анимация или нечисловая фаза/скорость пропускаются, существующий цикл не закрывается. Формат пакета, выбор валидных движений и мягкая коррекция фазы не меняются. Совпадающие валидные индексы с разным смыслом требуют отдельного сопоставления по именам; эта защита того не решает.

check-native-monster-motion исполняет настоящий helper и полный netcoop_play_motion с узким mock интерфейса renderer. Проверяются неверные slot/index, пустая и заменённая по тому же адресу библиотека, NaN/Inf, отсутствие visual, правильный запуск и повтор без перезапуска existing blend. Прямое чтение definitions в mock ограничено at(), поэтому выход за границу завершит тест ошибкой. Нативный запуск только в Actions, GCC/MSVC. Без нового дампа нельзя объявить это доказанной причиной конкретного вылета пользователя.

Windows остановился на C4244 в конструкторе тестовой std::pair<u16,u16> из int-литералов (/WX); входы стенда приведены явно к u16 без изменения игрового кода и подавления предупреждений. Нужен повтор MSVC и полной сборки. Новый стенд старых пакетов Windows уже прошёл.
