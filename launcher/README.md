# Лаунчер и установщик (Rust)

Внешний вид пока повторяет лаунчер New Way (позже переделаем под себя). Внутри своя система
доставки, рассчитанная на игру весом 90+ ГБ.

```
launcher/
  app/              лаунчер + установщик (Tauri 2, один exe)
    brand.json      название, адреса серверов, ключ, рендеры, ссылки — всё настраиваемое
    ui/             интерфейс (HTML/CSS/JS), assets/bg.jpg и logo.png — заменяемые
  crates/gamesync/  движок загрузки и проверки
  crates/packer/    утилита издателя: упаковка релиза, тестовый сервер, консольный клиент
  keys/             ключи подписи (secret.key НЕ публиковать и НЕ терять)
```

## Как устроена доставка

| | New Way (старый) | Этот лаунчер |
|---|---|---|
| Единица загрузки | файл целиком (SHA-256) | чанк ~1 МБ (BLAKE3), нарезка по содержимому (FastCDC) |
| Обновление архива 1,5 ГБ, где изменилась одна текстура | качается весь архив | качаются только изменённые чанки |
| Одинаковые данные в разных файлах | качаются повторно | хранятся и качаются один раз |
| Сжатие | — | zstd-19 на сервере; уже сжатое/шифрованное хранится как есть |
| Обрыв связи | перекачка файла | докачка: `.nwpart` проверяется по чанкам, продолжается с места |
| Повреждённый файл | перекачка целиком | чинится на месте, качаются только битые чанки |
| Подмена сервера | `AllowInvalidCertificate: true` | релиз подписан ed25519, каждый чанк сверяется по хешу |
| Лишние файлы в папке | удаляются (так снеслась ваша распаковка) | удаляются только файлы прошлой версии; чужое не трогаем |

Загрузка: N параллельных соединений (по умолчанию 16), соседние чанки склеиваются в один
Range-запрос до 32 МБ, распаковка и проверка идут на всех ядрах, запись сразу на место (без
временной копии и двойного места на диске). При ошибке — повтор с паузой и переключение на
другое зеркало; битый чанк перекачивается отдельно.

Обновление: всё, что уже есть на диске (старые версии файлов, соседние файлы), собирается
локально копированием, по сети идёт только новое. Быстрая проверка при запуске сравнивает
размер и время изменения (секунда на 55 тыс. файлов); полная («Проверить файлы») хеширует всё.

Сервер — любой статический хостинг с поддержкой HTTP Range: nginx, Caddy, S3/R2/B2, CDN.
Своего серверного кода не нужно. Можно указать несколько зеркал в `base_urls`.

## P2P: раздача без белого IP

Сервер и лаунчеры связываются через [iroh](https://iroh.computer): адрес сервера — публичный
ключ узла (`p2p://846f…`), а не IP. iroh пробивает NAT напрямую (hole punching); если не
получается, трафик идёт через relay-сервер (по умолчанию публичные relay от n0 — бесплатные, для
большой нагрузки лучше поднять свой). Белый IP, Radmin и проброс портов не нужны.

Лаунчеры игроков с последней версией раздают её друг другу, как торрент: при загрузке лаунчер
спрашивает у сервера-трекера список таких игроков и качает у них, а чего у них нет — с сервера.
Каждый чанк сверяется по BLAKE3, так что подсунуть битые данные игрок не может. Раздачу игрок
выключает кнопкой «Раздача» в лаунчере. Другие игроки при этом видят его IP-адрес (как в торренте).

## Сервер и веб-панель

`Kall\start_server.bat` → `server\NetAnomalyServer.exe`. При первом запуске откроется панель
`http://127.0.0.1:8787` (доступна только с этого ПК) и попросит задать пароль. В панели:

- **Обзор** — версия, размер, сколько игроков раздают, отдано трафика, адрес `p2p://…` и ключ
  для `brand.json`;
- **Публикация версии** — указать папку игры и номер версии, нажать «Опубликовать»;
- **Новости** — добавить/изменить/удалить, с картинкой; появляются в лаунчере сразу;
- **Игроки** — кто сейчас раздаёт игру;
- **Настройки** — название, число одновременных раздач, HTTP-зеркало (только при белом IP),
  смена пароля.

Настройки сервера — `server\server_data\config.json`, ключ узла — `server_data\node.key`
(от него зависит адрес `p2p://…`; потеряете — придётся пересобрать лаунчер с новым адресом).

## Выпуск версии

```bash
# один раз: ключи (public_key из вывода — в app/brand.json)
dist/packer.exe keygen --out keys

# каждый релиз: папка игры → папка publish
dist/packer.exe pack --input "D:/Game" --out "D:/publish" --version 1.0.0 --key keys/secret.key --product NetAnomaly --exclude "_client_/**"

# вместе с новым лаунчером (автообновление у игроков):
dist/packer.exe pack ... --launcher dist/NetAnomalyLauncher.exe --launcher-version 1.0.1
```

Залейте содержимое `publish/` на хостинг (новые `packs/*.pack`, `manifests/*`, затем `latest.json`
последним). Публикуйте в ту же папку `publish` — `chunkstore.bin` там помнит уже выложенные
чанки, и новый релиз добавляет только изменения. Неизменённые файлы при повторной упаковке не
перечитываются.

`news.json` в корне publish — новости в лаунчере:
`[{"title": "...", "date": "01.10.2026", "text": "...", "image": "news/1.jpg", "link": "https://..."}]`

## Локальная проверка

```bash
dist/packer.exe serve --dir D:/publish --port 8080
dist/packer.exe install --url http://127.0.0.1:8080/ --dir D:/test_install --pubkey <public_key>
dist/NetAnomalyLauncher.exe --dir D:/test_install     # лаунчер на любой папке
```

## Сборка

```powershell
./build.ps1      # → dist\NetAnomalySetup.exe, NetAnomalyLauncher.exe, NetAnomalyServer.exe, packer.exe
```

**NetAnomalySetup.exe** — веб-установщик: маленький, лаунчера внутри нет. При установке он
связывается с сервером (по P2P), проверяет подпись релиза, скачивает опубликованный лаунчер,
сверяет хеш и ставит его: ярлыки, запись в «Установка и удаление программ» (без прав
администратора). Установщик всегда ставит свежий лаунчер — пересылать его заново после
обновлений не нужно.

**Обновление лаунчера**: соберите новый `NetAnomalyLauncher.exe`, затем в панели сервера
«Публикация версии → Лаунчер» укажите путь к нему и версию (или
`packer launcher --out <publish> --exe <exe> --version 1.0.1 --key keys/secret.key`). Игру
перепаковывать не нужно. Лаунчеры игроков при следующем запуске сравнят хеш своего exe с
опубликованным и обновятся сами.

Удаление — ярлык «Удалить …» в «Пуске» (лаунчер с ключом `--uninstall`): спрашивает, удалять ли
файлы игры. Нужен WebView2 (есть в Windows 11 и в обновлённой Windows 10).

## brand.json

`product`, `title`, `exe_name` — название; `base_urls` — зеркала; `public_key` — ключ проверки
подписи; `renderers` — кнопки рендера (exe + аргументы); `connect_args` — шаблон аргументов
подключения `{ip} {port} {login} {password}` (пусто — не передаются); `keep` — что никогда не
удаляется; `clean_on_update` — что чистится при смене версии; `connections` — число соединений.
Пароль сервера хранится зашифрованным (Windows DPAPI).
